# NFC Note

Небольшое Android-приложение для передачи короткого текста между двумя телефонами
**напрямую через NFC**. Kotlin, Jetpack Compose, Material 3. Без аккаунтов, серверов,
рекламы, аналитики, Bluetooth и Wi-Fi. Лицензия MIT.

**[Скачать APK из GitHub Releases](https://github.com/yurkai/nfc-note/releases)**

> Экспериментальный MVP. Сборка и unit-тесты проверяются автоматически, но обмен
> между двумя физическими телефонами пока **не проверен**. Первый выпуск — prerelease.
> Эмулятор не заменяет испытание NFC-радиоканала.

## Как пользоваться

1. Скачать APK на оба телефона из Releases и установить, разрешив установку из выбранного источника.
2. Включить NFC, разблокировать оба телефона и открыть NFC Note.
3. На первом выбрать **Send**, ввести текст и нажать **Prepare to send**.
4. На втором выбрать **Receive**. Приложить области NFC-антенн друг к другу
   (обычно на задней панели) и удерживать до результата.
5. На получателе появится текст и **Copy**, на отправителе — **Sent** после ACK.

Пример: `Привет 🌍` на первом телефоне → Prepare to send → соприкосновение антенн →
тот же текст на втором. При обрыве до получения полного сообщения частичный текст
не показывается. Подготовить отправку заново можно той же кнопкой.
Если подтверждение потеряно, сообщение могло дойти: сначала проверьте второй телефон,
чтобы не отправить дубликат. Полученный текст можно убрать кнопкой **Clear**.

Лимит **1024 байта UTF-8**, а не символа. Кириллица и emoji занимают несколько байт.
Отправка одноразовая; подготовка истекает через 60 секунд и отменяется при уходе
из приложения, повороте экрана, блокировке, смене режима, редактировании или Cancel.
После возвращения нужно снова нажать Prepare to send.

## Совместимость и реализуемость

- Android 10+ (minSdk 29), target/compile SDK 37 (Android 17).
- Получателю нужен NFC с ISO-DEP; отправителю — **NFC HCE**. Наличие NFC само по себе
  не гарантирует HCE. Без NFC приложение показывает объяснение; без HCE можно принимать.
- Отправитель использует `HostApduService`, получатель — `enableReaderMode()` с NFC-A
  и `FLAG_READER_SKIP_NDEF_CHECK`. Reader Mode отключает эмуляцию карты на получателе.
- Используется ISO-DEP/APDU, **Android Beam не используется**.
- HCE объявлен в категории `other`, не требует назначения приложением-кошельком.
  В foreground запрашивается `setPreferredService`; в фоне подготовленного текста нет.
- Оба экрана должны быть включены и разблокированы. Secure NFC, Observe Mode кошелька,
  размещение антенн, прошивка и производитель могут влиять на доступность и стабильность.
- APDU выполняются вне UI-потока. Тайм-аут transceive 2,5 секунды, всего сеанса — 12 секунд.
  При уходе в фон соединение закрывается, запоздалые результаты игнорируются.

Архитектура проверена по официальной документации:
[HCE](https://developer.android.com/develop/connectivity/nfc/hce),
[Reader Mode](https://developer.android.com/reference/android/nfc/NfcAdapter#enableReaderMode(android.app.Activity,%20android.nfc.NfcAdapter.ReaderCallback,%20int,%20android.os.Bundle)),
[IsoDep](https://developer.android.com/reference/android/nfc/tech/IsoDep).
Фактическая совместимость устройств ещё требует [испытаний](docs/device-test-plan.md).

## Приватность и ограничения безопасности

В manifest единственное разрешение приложения — `android.permission.NFC`.
**INTERNET отсутствует**. Нет сторонних SDK, телеметрии, привилегированных API,
истории сообщений, записи содержимого в логи или намеренного сохранения на диск.
Сообщения находятся в памяти процесса; состояние текста не входит в saved instance state.
Резервное копирование отключено, скриншоты и превью последних приложений защищены FLAG_SECURE.
Копирование — явное действие пользователя: текст попадёт в системный clipboard и может
быть доступен другим приложениям по правилам Android. Помечается чувствительным.
Клавиатура/ОС могут обрабатывать ввод независимо от NFC Note.

**В MVP нет шифрования и взаимной аутентификации. Малая дистанция NFC не гарантирует
конфиденциальности.** Любой совместимый NFC-ридер рядом может прочесть намеренно
подготовленное сообщение. SHA-256 проверяет целостность, но не удостоверяет отправителя.
ACK — подтверждение протокола, а не доказательство личности получателя или доставки
«ровно один раз». Не передавайте секреты. Удаление ссылок/обнуление буферов не гарантирует
полного удаления всех копий текста из памяти JVM.

## Сборка

Требуются JDK 17+, Android SDK Platform `android-37.0`, Build Tools `36.0.0`.
Используются AGP 9.4.1, встроенный Kotlin/Compose compiler 2.4.21, Gradle 9.6.0,
Compose BOM 2026.09.00, Activity Compose 1.13.0. Версии зафиксированы.

```sh
git clone git@github.com:yurkai/nfc-note.git
cd nfc-note
export ANDROID_HOME="$HOME/Library/Android/sdk" # либо путь к вашему SDK
# JAVA_HOME должен указывать на JDK 17+; можно использовать JBR Android Studio
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
Debug использует отдельный applicationId с суффиксом `.debug` и может стоять рядом
с release. Для проверки на двух телефонах установите одну и ту же сборку на оба.

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Для release задать переменные (не коммитить значения):
`NFC_NOTE_KEYSTORE` (абсолютный путь), `NFC_NOTE_STORE_PASSWORD`, `NFC_NOTE_KEY_ALIAS`,
`NFC_NOTE_KEY_PASSWORD`, затем `./gradlew assembleRelease`.
Без ключа release-сборка остаётся **unsigned**; workflow публикации требует ключ и
проверяет подпись через `apksigner`. Debug-ключ для публичных релизов не используется.

## GitHub Actions и подпись

Push/PR запускает unit-тесты, Android Lint и debug-сборку. APK и отчёты доступны как
Actions artifacts. Тег `v0.1.0` запускает release workflow: тесты, lint, подписанный APK,
проверка подписи, SHA256SUMS и публикация GitHub prerelease с описанием изменений.
Версия тега должна совпадать с `versionName` в `app/build.gradle.kts`.
Для нового релиза увеличить `versionCode`, обновить `versionName` и release notes.

В GitHub Secrets нужны:

| Secret | Значение |
| --- | --- |
| `NFC_NOTE_KEYSTORE_BASE64` | Base64 постоянного release-keystore |
| `NFC_NOTE_STORE_PASSWORD` | Пароль хранилища |
| `NFC_NOTE_KEY_ALIAS` | Alias ключа |
| `NFC_NOTE_KEY_PASSWORD` | Пароль ключа |

Keystore создаётся и хранится **вне репозитория**. Сделайте зашифрованную резервную
копию keystore и паролей в надёжном месте. GitHub Secrets не служит резервной копией:
прочитать загруженное значение обратно нельзя. Потеря ключа не позволит подписать
совместимое обновление. Ограничьте доступ к Actions и защищайте изменения workflow:
код release workflow имеет доступ к ключу подписи.

Проверка скачанного APK: `sha256sum -c SHA256SUMS` (macOS: `shasum -a 256 -c SHA256SUMS`).
Суммы подтверждают совпадение с опубликованным файлом, не заменяют доверие к источнику.

## Код и тесты

- `ui/NoteScreen.kt` — Compose-интерфейс и системная тема.
- `MainActivity.kt` — жизненный цикл, Reader Mode, IO и настройки NFC.
- `nfc/TransferStore.kt` — синхронизированное состояние отправки только в памяти.
- `nfc/NoteHceService.kt` — Android HCE без собственной бизнес-логики.
- `protocol/Protocol.kt` — независимые от Android кодирование и конечный автомат APDU.

Unit-тесты покрывают Unicode, границы размера, фрагментацию, неверные команды,
неверный AID, порядок запросов, checksum, ACK, истечение подготовки, отмену,
обрыв транспорта и потерю подтверждения. [Описание протокола](docs/protocol.md).
[План проверки на физических устройствах](docs/device-test-plan.md).
